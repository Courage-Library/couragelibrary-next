## 2. Per-dependent decisions

| Dependent | Decision (applied) |
|---|---|
| `discussion_threads.article_id` | New column `learning_document_id uuid NULL` with FK → `learning_documents(id)` ON DELETE SET NULL; values preserved (0); `article_id` dropped; `idx_threads_article` → `idx_threads_learning_document`; `check_exact_single_context` now counts `learning_document_id`. `context_type 'ARTICLE'` is kept and now means a learning document. |
| `fn_create_discussion_thread` | Signature unchanged (there was no separate article overload to drop). `ARTICLE` context requires a **PUBLISHED** learning document with a current published version and writes `learning_document_id`. **074:** the activity-log insert was removed because it could never succeed (see below). |
| `batch_curriculum_assignments.article_id` | Same pattern; `chk_assignment_content_xor` counts `learning_document_id`. `fn_create_batch_assignment` maps `ARTICLE` → `learning_document_id`. |
| `daily_study_recommendations.resource_id` | Same pattern (`learning_document_id`, ON DELETE SET NULL). |
| `fn_generate_daily_recommendations` | **No student-reachable caller → deprecated.** Same signature, SECURITY DEFINER and grants; it returns `{success:true, deprecated:true, tasks_generated:0, …}` with `RAISE NOTICE 'deprecated…'` and writes nothing. Backlog: **LOOP-1**. |
| `course_lessons.learning_resource_id` | Preserved (0 values), column + unique + FK dropped; `learning_document_id` (072) stays. |
| `fn_complete_course_lesson` | Uses `learning_document_id` only; the topic comes from `learning_documents → learning_units.topic_id`. **074:** its completion event now uses the deployed `learning_activity_events` shape (see below). |
| `fn_reconcile_search_indexes` | Sections 1+2 now index **servable** `learning_documents` only: PUBLISHED, current version published with review_status PUBLISHED, unit active. Entries are ARTICLE with `/articles/<slug>`. Stale `RESOURCE` entries and ARTICLE entries that are no longer servable are set unpublished. DRAFT documents are never indexed. Courses, announcements and discussions are unchanged. |
| `fn_publish_article_version` | Dropped. Its full definition is preserved in the 073 header comment and in the rollback. |

- **Rewritten functions:** SECURITY DEFINER and `search_path = public, pg_temp` as before. `CREATE OR REPLACE` kept every ACL, including the existing `PUBLIC` execute on `fn_create_batch_assignment` (unchanged, not widened).
- **ON DELETE SET NULL combined with the single-context / XOR checks:** deleting a learning document that a thread or assignment references would leave zero contexts, so the check makes the delete fail (RESTRICT in effect). Documents are archived, not deleted, so this is accepted and noted.
- **Discovered drift (fixed by migration 074, function bodies only).** The DB tests exposed two defects in the functions being re-pointed:
  1. **`fn_create_discussion_thread` has never worked.** It inserts into `learning_activity_events` without the NOT NULL `resource_slug` and, for non-TOPIC contexts, without `topic_id`. Its event type `COMMUNITY_DOUBT_ASKED` is also rejected by `learning_activity_events_event_type_check`. Fix: the insert is removed.
  2. **`fn_complete_course_lesson`'s completion event used columns that were never deployed** (`resource_type`, `resource_id`, `idempotency_key`, `event_payload`) and event type `LESSON_COMPLETED`. Before 073 this path was unreachable (0 resource-topic rows); after re-pointing it would have failed on every lesson that has a document. Fix: it now writes `(topic, resource_slug = document slug, 'ARTICLE_COMPLETED', metadata)`, once per user + lesson.

  073 was already in the ledger, so these went into a separate function-only migration **074**: no schema, policy or grant change, with backup, dry-run, apply and ledger. **This is a deviation from "migration 073 only"; please confirm.**

## 6. Content Studio compile resolvers (backlog Q5)

| Piece | Behaviour |
|---|---|
| `QuestionReferenceService` | No placeholder path. No client → `REFERENCE_CATALOG_UNAVAILABLE`. Unknown → `QUESTION_NOT_FOUND`. Not current / not PUBLISHED / question not `published` → `QUESTION_INACTIVE`. Lookup failure → `INVALID_QUESTION_REFERENCE` (no raw DB text). Every message names the reference. |
| `AssetReferenceService` | No placeholder path. The asset must be a `learning_assets` row with status **PUBLISHED**, in the private `learning-artifacts` bucket, whose storage object **exists**. Otherwise `ASSET_NOT_FOUND` / `ASSET_INACTIVE` / `REFERENCE_CATALOG_UNAVAILABLE`. |
| `services/learning/reference-catalog.ts` | real clients over `question_versions ⋈ questions` and `learning_assets` + storage |
| `ControlledContentCompiler.verifyReferences` | used by compile and again by publish |

**Callers:**
- Create draft, save draft, the AI importer and `compileVersion` all pass the real catalogs.
- `compileVersionAction` now returns **VALIDATION** naming the unresolved references. Before this, it returned `success: true` even when the compile failed.
- `publishVersion` **re-verifies** references from the stored source spec before any update, and throws `[UNRESOLVED_REFERENCES] …`. This closes the old path where an APPROVED version could be published without a successful compile.

Messages avoid DB-error keywords, so `toActionFailure` surfaces them as VALIDATION and does not replace them with the generic DB message. `learning_assets` currently has 0 rows, so any asset reference fails closed until real assets exist.
