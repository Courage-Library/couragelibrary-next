# Permanent gates

Every code phase must pass these before it is committed. Phase-specific suites are added on top. Run them against a local production build; never against production.

**Live gates run ONLY through the runner** (`docs/testing/LIVE_GATES.md`): `npm run build`, then `node scripts/live/with-server.cjs --port=3100 -- "<gate 1>" "<gate 2>" …` — free-port check, health confirmed (≤ 120 s) before any gate, ≤ 15 min per gate, server always stopped. No hand-started servers or unbounded wait loops.

**Rules:**
- **No vacuous passes** (architect, GATE-HYGIENE-1, 2026-10-18). A check that passes having scanned 0 items is a defect, not a pass.
  - A set that should never be empty gets a minimum-coverage assertion (files, links, chunks, rows, titles).
  - A set that can legitimately be empty prints `WARN  VACUOUS (0 items): …` and is never a silent PASS.
  - Every scan reports how many items it covered.
- **Loop #65 (CI-first, architect 2026-10-21):**
  - Locally run the offline gates only: tsc, lint, build, offline suites, ratchets, no-personal-data, design ratchet.
  - Then the pre-authorised commit + push. CI runs the live gates on every push to `main` (code changes; docs-only skipped).
  - A phase is CLOSED only when the owner reports CI green.
  - Local live gates only when cheap and needed for development.
  - (Exception E-1 cleared by CI run #2.)
- **Commit procedure (LOCAL-ONLY-1):** stage explicit paths only; never "Stage All" / `git add -A` / `git add .` with untracked files present. A local-only file must be listed in `docs/ops/LOCAL_ONLY_PATHS.txt` **and** git-ignored the moment it is created.
- **A new gate's first run must be proven non-writing** (architect, SECDEF-S2-2, 2026-10-20).
  - Before a new gate makes any committed client call (PostgREST / HTTP / server action), its first run is either read-only or entirely inside rolled-back transactions.
  - Probes that would execute a function the gate tests for denial run only once the catalogue shows the grant is gone.
  - **Why:** a pre-revoke PostgREST probe executed 14 functions as qa-student (SECDEF-S2-2 report §1.5).
- **Never run scripts that disable TLS verification.** See the inventory in `docs/reports/hotfix/HOTFIX2_REPORT.md`.
- **Student-data gate order** (architect, 2026-10-17). The E2E journey and the smoke fixture share qa-student and the `ssc-cgl-daily-monday-mock` mock, so always run them in this order, all through `with-server.cjs`:
  1. `cleanup-student` (`E2E_KEEP_USER=1`)
  2. E2E journey (`student-journey.cjs`)
  3. lineage (`assert-mistake-lineage.cjs`)
  4. drill gates (`test_drill1.cjs`, `student-drill.cjs`)
  5. `cleanup-student` (`E2E_KEEP_USER=1`)
  6. `ensure-student-fixture`
  7. student-mistake smoke; **leave the fixture** in place.

  If the fixture exists when the journey starts, the mock offers no "I Agree & Start Test" and the journey fails.
- **Never create throwaway auth users.** Use only the permanent QA identities (`docs/testing/QA_IDENTITIES.md`), and run `cleanup-student.cjs` with `E2E_KEEP_USER=1`.
